# 2.5c แบบร่าง: ระบบได้สูตร + จดหมายจากเชฟ

> 23 พ.ย. 2026 · แทนที่ "โหมดลองผสม" เดิม (ผู้ใช้ตัดออก: ขึ้นกับดวงเกินไป)

## 1. ทำไม

- ผู้ใช้ไม่อยากให้การได้สูตรขึ้นกับดวง อยากให้ได้สูตรจากหลายทาง ชิลบ้าง ง่ายบ้าง ผูกกับเนื้อเรื่องและเนื้อหาอื่นของเกม
- ตอนนี้สูตรปกติ ~67 สูตรยังไม่มีทางได้เลย (มีแค่ 8 สูตรเริ่มต้น + Debug) และเมนูนิยมสุ่มสูตรที่ยังไม่รู้มาให้เห็นเป็น `???` แล้ว
- เนื้อเรื่อง: ตัวเอกเรียน Computer Science ฝึกงานล้มเหลว มีแผลใจเรื่องการทำงานร่วมกับคนอื่น เรียนจบแล้วมาเปิดร้านอาหารนานาชาติในชนบท / โลกมีอินเทอร์เน็ต
- เกมทำเป็นภาษาอังกฤษ (ขายทั่วโลก) → ข้อความในเกมทั้งหมดเป็นอังกฤษ

## 2. ทางได้สูตร (ตัดสินแล้ว)

คอลัมน์ `Obtain` ในตาราง Recipes (Z) กำหนดทางของแต่ละสูตร ค่าตั้งต้นจัดไว้แล้ว เฟส 3 ค่อยขัดเกลา

| Obtain | คืออะไร | ทำเมื่อไร |
|---|---|---|
| Starter | สูตรเริ่มต้น 8 สูตร | มีแล้ว |
| **Chef Mail** | เชฟผู้มีประสบการณ์ส่งจดหมายพร้อมสูตร + เล่าเรื่องตัวเองกับสูตรนั้นสั้นๆ เงื่อนไข เลเวลร้าน ≥ n **และ** ชื่อเสียง ≥ n → จดหมายมาถึงตู้ตอนเช้าวันถัดไป | **2.5c** |
| Shop Book | ซื้อสมุดสูตรที่ร้านค้า/พ่อค้าเร่ | 2.6b |
| Monster Pages | มอนสเตอร์ดรอปเศษหน้าสูตร ครบ 3 หน้า = 1 สูตร / แท็บ Recipes วางเมาส์ขึ้น `2/3` + ภาพสูตรค่อยๆ เผยตามหน้าที่มี | เฟส 3 |
| Boss | ตีบอสครั้งแรก = ได้สูตรแน่นอน | เฟส 3 |
| Dig Box | ขุดเจอกล่องข้าวเก่า/ไทม์แคปซูล (แบบ geode) มีโน้ตสูตรของเจ้าของที่ดินคนเก่า | เฟส 3 |
| Fishing Bottle | ขวดจดหมายจากการตกปลา | เฟส 3 |
| Food Truck | ฟู้ดทรักต่างชาติแวะมา กินจานเขาครบ N ครั้ง = แกะสูตรได้ | เฟส 3 |
| Request Board | กระดานคำขอของชาวบ้าน | เฟส 3 |
| Story / Event / Festival | **สูตรลับเท่านั้น** side story, อีเวนต์ลับ, ชนะแข่งทำอาหารในเทศกาล | เฟส 3 |

- Dig Box / Fishing Bottle: **สุ่มเฉพาะสูตรในกลุ่มที่ยังไม่รู้** (ไม่มีสูตรซ้ำ) รู้ครบกลุ่มแล้วได้ของอย่างอื่นแทน (ข้อเสนอ ผู้ใช้ยังไม่ได้ยืนยัน ตัดสินตอนเฟส 3)
- ไอเดียเฟส 3 ที่ไม่ใช่ทางได้สูตร: สิ่งประดิษฐ์ไฮเทคของตัวเอก (เตาอัตโนมัติ, เครื่องรดน้ำอัตโนมัติ, เครื่องพรวนดินแทนจอบ)
- คอลัมน์ `Unlock` / `Rumor` เดิมยังอยู่ ข้อความข่าวลือเอาไปเป็นคำใบ้ของอีเวนต์/เทศกาลได้

3. `MailSystem` + ตู้จดหมาย + หน้าต่างอ่านจดหมาย (อ่านซ้ำได้ตลอด)
4. เซฟ v7
5. คำใบ้ `???` ของเมนูนิยมบอกว่าสูตรนั้นหาได้จากทางไหน
6. ร่างจดหมายภาษาอังกฤษ 20 ฉบับ + เชฟ 6 คน ลงตาราง

**ไม่ทำ (non-goals)**: ทางได้สูตรอื่นนอกจาก Chef Mail (มีแค่ค่าใน enum) / การคิดชื่อเสียงจริง (2.6) / ภาพเชฟ / UI สวย (เฟส 4)

**ห้ามเกิด (anti-goals)**: ผู้เล่นพลาดจดหมายถาวร / จดหมายหายหลังโหลดเซฟ / ได้สูตรซ้ำหรือได้สูตรที่รู้แล้วทางจดหมาย

## 4. ข้อมูล

**ตาราง Recipes** (มีแล้ว Z–AC): `Obtain`, `Obtain Note`, `Mail Shop Lv`, `Mail Reputation` / **เพิ่ม** AD `Chef` (รหัส เช่น `chef_th`), AE `Letter` (เนื้อจดหมายภาษาอังกฤษ ขึ้นบรรทัดใหม่ได้)

**ชีตใหม่ Chefs**: `chef_id`, `Name`, `Country`, `Sign-off` (คำลงท้าย), `Bio` (โน้ตตัวละคร ไม่แสดงในเกม) → CSV `Assets/Data/Chefs.csv`

**`enum RecipeSource`** (ต่อท้ายเท่านั้น): Starter, ChefMail, ShopBook, MonsterPages, Boss, DigBox, FishingBottle, FoodTruck, RequestBoard, Story, Event, Festival

**`RecipeData` เพิ่ม**: `obtainSource`, `obtainNote`, `mailShopLevel`, `mailReputation`, `chef` (ChefData), `letterBody` (TextArea)

**`ChefData`** (ScriptableObject, `Assets/Chefs/`): `chefId`, `displayName`, `cuisine`, `signOff`, `portrait` (ว่างไว้), `bio`
- ตัว import สร้าง/อัปเดตตาม chef_id ไม่เขียนทับ portrait

**ตัว import**: หาคอลัมน์จากชื่อหัวเหมือนเดิม / ไม่มีคอลัมน์ = เตือน + ไม่แตะค่าเดิม / `Obtain` ว่างหรือไม่รู้จัก = Starter ถ้า inDemo ไม่งั้นเตือน / Chef Mail ที่ไม่มีเชฟหรือเนื้อจดหมาย = เตือน

## 5. ShopProgress (บนวัตถุ ShopManager)

- `Level` (เริ่ม 1), `Reputation` (เริ่ม 0, ไม่ติดลบ), `SetLevel`, `AddReputation`, `SetReputation`, event `OnProgressChanged`
- Debug (คลิกขวาหัว): `Debug: Level +1`, `Debug: Reputation +100`, `Debug: Reset Progress` + ช่อง Inspector ตั้งค่าแล้วกด `Debug: Apply Values`
- 2.5c ยังไม่มีอะไรเพิ่มค่าเอง

## 6. MailSystem (singleton วัตถุ MailSystem)

- **ตอนเช้า (`OnDayStarted`)**: หาสูตร ChefMail ที่ **ยังไม่ได้รับจดหมาย** + **ยังไม่รู้สูตร** + `Level ≥ mailShopLevel` และ `Reputation ≥ mailReputation` → เรียงตาม (เลเวล, ชื่อเสียง, ลำดับในฐานข้อมูล) → ส่งเข้าตู้ไม่เกิน `maxLettersPerMorning` = 2 ที่เหลือมาเช้าถัดไป
  - เช็กตอนเช้าแทนตอนจบวัน → ครบเงื่อนไขวันนี้ = มาเช้าพรุ่งนี้ตามที่ผู้ใช้ต้องการ และ**ไม่ต้องเซฟคิวรอส่ง** (คำนวณใหม่ทุกเช้า) / โหลดเซฟ = เริ่มวันใหม่ = เช็กตามปกติ
  - มีจดหมายใหม่ = แจ้งเตือน `You've got mail! (2)`
- **เก็บ**: `received` (ลำดับที่ได้, วันที่ได้) และ `read`
- **อ่านครั้งแรก** = `RecipeBook.Learn` + แจ้งเตือน `New recipe: Pad Thai!` / อ่านซ้ำไม่เกิดอะไรเพิ่ม
- event `OnMailReceived`, `OnLetterRead` / `UnreadCount`
- Debug: `Debug: Check Mail Now` (ส่งจดหมายที่เข้าเงื่อนไขทันที ไม่จำกัดจำนวน) / `Debug: Deliver All Chef Letters` / `Debug: Print Mail Status`

**ทางได้สูตรทุกทาง** (ตอนนี้และอนาคต) จบที่ `RecipeBook.Learn` แล้วแจ้งเตือน → เพิ่ม `RecipeBook.Learn(recipe, notify)` ให้ทุกทางใช้แบบเดียวกัน

## 7. ตู้จดหมาย + หน้าต่างจดหมาย

- `Mailbox` (IInteractable, Collider ทึบ) วางหน้าร้านด้านนอก (ตัว builder วางใกล้ `Outside_Front` ผู้ใช้ย้ายเองได้) / มีจดหมายยังไม่อ่าน = `!` เหนือตู้ / อยู่ใกล้ = `[E] Mail`
- E = เปิด `MailUI` (เปิดได้แม้ไม่มีจดหมายใหม่ เพื่ออ่านซ้ำ) / ระหว่างเปิดร้านเปิดไม่ได้
- หน้าต่าง: ซ้าย = รายการจดหมาย ใหม่สุดบนสุด ฉบับยังไม่อ่านมี `NEW` สีทอง / ขวา = จาก (ชื่อเชฟ · ชาติ), วันที่ได้ (`Day 12`), เนื้อจดหมาย (เลื่อนได้), คำลงท้าย, บรรทัด `Recipe: Pad Thai` / คลิกฉบับ = อ่าน (ฉบับแรกยังไม่อ่านถูกเลือกไว้ก่อน)
- ระหว่างเปิด: นาฬิกาหยุด, เดินไม่ได้, เปิดกระเป๋า/Hotbar ไม่ได้ (เหมือนหน้าต่างเมนู) / Esc หรือปุ่ม Close ปิด
- ไม่มีจดหมายเลย = `No letters yet.`

```
┌ Mail ────────────────────────────────────────────┐
│ NEW Chef Somchai – Pad Thai │ From: Chef Somchai · Thailand │
│     Chef Kenji – Ramen      │ Day 12                       │
│     Chef Somchai – Kaprao   │ Dear young owner, ...        │
│                             │ ...                          │
│                             │ — Somchai                    │
│                             │ Recipe: Pad Thai             │
│                                              [Close]       │
└──────────────────────────────────────────────────┘
```

## 9. คำใบ้เมนูนิยม

`PopularDishes.GetDisplayName` สูตรที่ยังไม่รู้: `??? (Japanese dessert) · a chef may write` — ข้อความสั้นตาม `RecipeSource` (ChefMail = `a chef may write`, ShopBook = `sold in shops`, Boss = `a boss guards it` ฯลฯ ตั้งได้ใน Inspector) / คำที่ลูกค้าถามหาไม่เปลี่ยน

## 10. ทางที่พิจารณา (เนื้อความจดหมาย/ข้อมูลเชฟอยู่ที่ไหน)

- A ทุกอย่างในตาราง: แก้ที่เดียว แต่ข้อมูลเชฟซ้ำทุกแถว
- **B (ผู้ใช้เลือก) ChefData แยกไฟล์ + เนื้อจดหมายในตาราง**: เชฟเป็นตัวละครใช้ซ้ำได้ (เฟส 3 มาเยี่ยมร้านได้) เนื้อความยังแก้ในตาราง
- C ไฟล์ใน Unity ทั้งหมด: จัดข้อความง่าย แต่แยกจากตาราง สร้างเอง 20 ไฟล์

## 11. Claude ตัดสินเอง (ผู้ใช้ตรวจได้)

- จดหมายไม่เกิน 2 ฉบับต่อเช้า / นาฬิกาหยุดตอนอ่าน / เปิดตู้ระหว่างเปิดร้านไม่ได้
- เชฟ 1 คนต่อ 1 ชาติ (6 คน) ชื่อและเนื้อจดหมายเป็นร่างแรก ผู้ใช้แก้ในตาราง
- เครื่องมือ `Tools > Second Serving > Build Mail System` สร้าง MailSystem + ShopProgress + prefab Mailbox + วางตู้ + MailUI + ผูก SaveManager (กดซ้ำได้ ไม่สร้างซ้ำ)

## 12. เพิ่มระหว่างทดสอบ (23 พ.ย.)

- ผู้ใช้: เมนูนิยมเห็นได้แค่ในหน้าต่างเลือกเมนู (17:00–19:00) = วางแผนหาวัตถุดิบไม่ทัน → ให้เห็นตั้งแต่เช้า
- **แจ้งเตือนตอนเช้า** `Popular today: * Som Tam · * ??? (Thai main) · a chef may write` (`PopularDishes.morningNoticeFormat`)
- **กระดานเมนูนิยมหน้าร้าน** `PopularBoard` (IInteractable) กด E = แสดง/ซ่อนรายการเหนือกระดาน เดินห่าง = ซ่อนเอง / `Build Mail System` สร้าง prefab + วางซ้าย OutsideFront 1.5
- `NotificationUI`: ข้อความหลายอันในเฟรมเดียว (จดหมาย + เมนูนิยมตอนเช้า) ต่อกันคนละบรรทัด ไม่ทับกัน
- คำใบ้ทางได้สูตร (`??? … · a chef may write`) = **ป้ายบอกทาง** ไม่ได้ปลดล็อกสูตร สูตรได้จากทางของมันเองเสมอ

## 13. ปรับระบบจดหมาย (24 พ.ย. ผู้ใช้ขอ)

- **จดหมายทั่วไป** `LetterData` (ผู้ส่ง, บรรทัดรอง, หัวข้อ, เนื้อความ, คำลงท้าย, ของแนบ, trigger) ใช้กับจดหมายตอนสลบ / แจ้งเทศกาล / NPC สนิท / NPC สนับสนุน (เฟส 3 เรียก `MailSystem.QueueLetter`) / จดหมายสูตรเชฟยังมาจากตาราง
- **สลบ** (`OnPassedOut`) = สุ่มจดหมาย trigger PassOut 1 ฉบับ มาเช้าถัดไป / ตัวอย่าง `Assets/Letters/passout_neighbor.asset` (ผู้ส่งชั่วคราว "A worried neighbor" **ไม่มีของแนบ** ผู้ใช้: แค่บอกว่ามี NPC เจอเราสลบแล้วพาไปส่งบ้าน/คลินิกในชนบท)
- **ของแนบแบบ Stardew**: ช่องด้านล่างตรงกลางจดหมาย ต้องคลิกรับ (สูตร = เรียนรู้, ไอเทม/อาหาร = เข้ากระเป๋า) / เงิน = เพิ่มตอน 2.6
- **ยกเลิกเพดาน 2 ฉบับต่อเช้า** จดหมายเชฟที่ถึงเกณฑ์มาพร้อมกันหมด
- **ตู้จดหมาย** = หยิบฉบับใหม่ (ยังไม่อ่านที่เก่าสุด) อ่านทีละฉบับ ไม่มี = "The mailbox is empty." / **โต๊ะคอมในห้องนอน** (`MailDesk`) = กล่องจดหมายที่อ่านแล้วทั้งหมด อ่านซ้ำได้
- Claude ตัดสินเอง: ของแนบที่ยังไม่รับ **ไม่หาย** รับทีหลังที่โต๊ะได้ / กระเป๋าเต็ม = ยังไม่ได้รับ แจ้งเตือน / แค่เปิดอ่าน = อ่านแล้ว แต่ของต้องกดรับ
- เซฟ v7: `mailIds` ("chef:<recipeId>" / "letter:<letterId>"), `mailDays`, `mailRead`, `mailClaimed` (บิต), `mailPendingIds`
